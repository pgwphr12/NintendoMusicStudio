# GBA software PCM voices

The GBA has four PSG voices and two Direct Sound FIFO outputs. A game's software mixer can combine many sample voices into those FIFO streams; PCM A/B must not be described as the individual instruments inside them.

This version recognizes the standard MP2K/m4a `SoundInfo` layout and up to12 fixed-size voice slots. The layout and envelope-side-gain transition are checked against the public primary references [m4a internal structures](https://github.com/pret/pokeemerald/blob/master/include/gba/m4a_internal.h) and [SoundMain mixer assembly](https://github.com/pret/pokeemerald/blob/master/src/m4a_1.s). The adapter is independently written and does not include game music, ROMs or copied mixer machine code.

The unmodified full-mix core remains authoritative. Independent isolated emulator instances suppress other slots only in the known PCM destination buffer; they do not clear sequencer channel flags or change allocation. The current slot is retained when the mixer writes its per-side envelope gains, because the sample loop can reuse the CPU register as a frequency accumulator. Unrecognized engine layouts fall back to hardware PCM A/B mixed outputs. They are not relabelled as fictitious instruments.

Display names are `PCM VOICE n`: these are polyphony slots, not permanently assigned MIDI tracks. The residual `EFFECTS / OTHER` preserves reverb, clipping, rounding and any non-attributed output, so summing all exposed voices retains the original mix. A game's unsupported driver may still produce only PCM A/B. Support is not claimed for every GBA music engine or HQ mixer variation.

Local read-only test: Super Mario Advance, Overworld —6 active PCM slots; original mix maximum error0 against hardware-only baseline over6seconds; recombined stems within0.0001/sample; residual energy ratio0.00000112835. Earlier partial attribution was rejected during development (residual ratio~0.86) until the envelope-context lifetime was corrected. No game files are included in packages. Three additional local Super Mario Advance2/3/4 tracks were checked and correctly remained hardware-only; those custom drivers are unresolved.

`NGMV_GBA_HARDWARE_ONLY=1` is a diagnostic fallback for comparison. `NGMV_GBA_MIXER_DEBUG=1` prints only aggregate layout/slot/write metadata to the diagnostic executable. Whole-program profiling and long-running performance across other games remain unverified.

## 1.4.2 offline note-metadata foundation (not yet editor import)

The explicit backend-only `prepareGbaInspection` / `drainGbaEvents` path observes standard-m4a PCM channel writes. It reports original MIDI key, translated key, velocity, driver gate ticks, slot generations, source-track address, raw frequency and stereo controls, ADSR, and bounded wave-header metadata. Note-on, gate-off, envelope/voice termination, repeated identical note starts and pitch/volume changes remain distinct. Slots are not assumed to be permanent musical tracks. Unsupported engines return false; malformed events, reversed clocks and queue overflow fail explicitly and preserve caller event output.

Collection is opt-in and reads memory only; no guest instructions, sample data or sequencer state are replaced. The authoritative audio remains unchanged. The core's optional elapsed-cycle counter counts dispatched CPU/DMA/hold event time plus pending CPU cycles at the write. This timestamps emulated writes, not a verified exact audible sample onset; CPU-instruction phase and audio-buffer latency still need calibration for a renderer.

Only PCM voices are covered. PSG event collection, complete song/tempo metadata, raw-frequency units, sample extraction/lifetime, dynamic engine-layout changes, common project integration and edited PCM rendering are unfinished. No GBA score is yet loaded into the piano roll, and no new GBA WAV editing completion is claimed. Sample type0 with readable nonzero-frequency data is flagged as PCM8; other formats and invalid bounds are not reinterpreted. Wave bytes are never exposed by this metadata API.

All87 observed sample headers were valid PCM8 in that example, and the original full-mix maximum sample error was0. Inspection restart reproduced event cycles/generations and the audio prefix. An initial test incorrectly assumed notes began within85ms; the corrected test searches within the bounded six-second reference instead. This does not generalize to other drivers or claim full musical reconstruction. Own-data fixtures check byte/halfword/word writes, sample bounds/type/loop validation, repeated keys, output canaries, overflow and time regression.


## 1.4.3 development: owned ROM samples

The explicit offline `copyGbaSample` inspection API copies signed PCM8 into an owned vector, after checking the exact observed WaveData header, supported encoding, nonzero raw frequency, loop bounds, backing ROM size and 32MiB cartridge mirror limits. It is unavailable before inspection opt-in. The three cartridge wait-state mirrors resolve against the loaded ROM; no raw guest pointer is exposed. RAM-generated samples and unknown encodings are rejected. Failure preserves the caller's sample, and unsupported backends preserve both sample and error. Calls belong to the decoder owner thread between rendering operations; concurrent use is not supported.

The copy owns its bytes after render, reset and decoder destruction. No game sample files are automatically written, and no private GSF/library/ROM/sample is distributed. Raw engine frequency remains raw: pitch/rate conversion is still unverified. This is not a shared-project instrument bank, sampler or GBA piano-roll import. PSG collection, mutable RAM sample capture, note lifetime recording, common Song/sample renderer/project/UI and edited GBA WAV remain unfinished.

Own-data tests check signed extrema, exact header/data offsets, ownership, three valid mirrors and odd-region offsets, truncated ranges, exact backing/mirror end, crossing rejection, unsupported status/type/zero frequency, metadata mismatch and output canaries. A read-only six-second standard m4a example copies87 notes referencing6 ROM samples/4778 bytes; repeated reads and reset match, and copies remain valid after decoder destruction. No source sound is modified. Forced allocation failure and concurrent decoder mutation are not tested.


## 1.4.5 development: original note lifetimes

GbaNoteRecorder is a read-only import intermediate, not another editable project model. It retains complete NoteOn metadata and source-track/sample identity, every pitch/stereo-volume event, optional gate release, and distinct natural end, stolen-slot end and capture-boundary truncation. Same-source overlapping slots remain separate. A same-key retrigger has a new generation; zero-cycle spans are retained rather than lengthened or silently dropped. Slot/generation gaps, stale/orphan events, repeated gate, reversed clocks, early boundaries and32768-note/262144-event overflow cause terminal failure with no partial successful result. Input chunking does not change lifetimes. Output remains unchanged on failure.

The inspection-only gbaEmulatedCycles query supplies the actual current emulated execution boundary, resets with inspection, and leaves output unchanged on unsupported/non-inspection paths. It is not a calibrated audible playback cursor: core prefetch may lead the output samples. Recorder finish marks remaining voices truncated at that observed boundary instead of inventing note-off/release events. Normal audio rendering is unchanged.

Control metadata can already belong to the next allocation before the new START write. The recorder therefore retains raw control metadata and counts binding changes; it does not blindly turn every write into an audible bend or change a previous note's original track/sample. The converter must resolve mixer-visible allocation state before applying those controls.

### Reference-only frequency investigation; actual conversion still disabled

Primary references read: [frequency function](https://github.com/pret/pokeemerald/blob/master/src/m4a.c), [scale/frequency tables](https://github.com/pret/pokeemerald/blob/master/src/m4a_tables.c), [mixer phase stepping](https://github.com/pret/pokeemerald/blob/master/src/m4a_1.s). Derivation from this reference: at key60 without fine shift, WaveData.freq is divided by1024; key72 doubles that result. The non-fixed mixer uses channel frequency times divFreq as a23-bit fractional increment. The fixed-rate tone flag instead advances one source sample per mixer sample. This is a reference-derived relationship, not yet a measured conversion guarantee for the local game/driver or audible onset. No copied game tables/code, inferred Hz conversion or fixed-rate substitution is included in the recorder. Mixer-visible rate/envelope/phase/timing calibration, PSG and actual shared Song import/UI remain unfinished.

The observed execution boundary is100516624 cycles and is reported as emulated time, not aligned audible end. All47 controls whose track/sample metadata differs from their note start match the next start on that slot in this example. This is evidence of allocation preparation, not permission to discard every control or assume same-binding controls are all audible. Raw events remain intact for later mixer-visible resolution. ## 1.4.6 development: mixer-applied state and measured source stepping

A separate explicit prepareGbaMixerInspection mode enables both original events and mixer-state queues. Normal playback and raw-event-only inspection do not allocate/collect mixer frames. Only the authoritative full-mix core is observed. Left per-side-gain completion is captured with the matching emulated channel register, locked SoundInfo and consumed START/active state; initialization, cleanup, right-gain-only and ordinary sequencer volume writes are not mix snapshots. Byte/halfword/word prospective writes never change guest memory. MixerState is a distinct kind, not a NoteOn; the lifetime recorder rejects it. Queues fail explicitly on overflow, reversed clocks, missing generation or malformed channel metadata, preserving caller output.

Each snapshot retains its original note generation/track/sample, applied envelope and stereo gains, source pointer/remaining count/Q23 fraction, mixer count/rate/divisor, master/reverb, emulated timer0 period and sound control. An observed SoundInfo lock-transition epoch groups related snapshots; it is not a calibrated audible frame number. Primary layout and mixer references: [structures](https://github.com/pret/pokeemerald/blob/master/include/gba/m4a_internal.h), [gain and phase stepping](https://github.com/pret/pokeemerald/blob/master/src/m4a_1.s). The independent forward PCM8 predictor uses the observed Q23 increment and exact one-shot/loop range; fixed-rate voices advance one source sample per mixer sample. Unsupported encodings/flags, malformed phase/count and overflowing rate arithmetic are rejected without output mutation.

Read-only six-second local example:1659 snapshots/6slots/87original allocations, zero original track/sample/MIDI binding mismatch,1572 adjacent same-generation phase/count/pointer comparisons with zero mismatch, zero gain mismatch and original full-mix maximum error0. The comparison validates local source stepping and applied per-side gain, not the raw WaveData root-key mapping, final audible onset, DMA buffer schedule, reverb or full original sound reproduction. No waveform pitch detector or game assets are distributed. Own fixtures cover phase fractions/loop/fixed/one-shot/unsupported state, write widths/context/status, output canaries, queue faults and no memory mutation. Reset and returning to raw-only mode are tested.

Next: project these mixer-applied rate/gain states and original lifetimes into automation supported by the EXISTING sampled Song. Preserve logical MIDI identity and sample phase, use observed applied state instead of blindly replaying setup writes, retain versions1/2/3, and keep unsupported PSG/RAM/other drivers explicit. Shared sampled UI/preview and real GBA-to-Song import remain unfinished. Emulated lock/write times are still not exact audible output times.


Final lock grouping check observes339 lock epochs containing those1659 mixer snapshots.
