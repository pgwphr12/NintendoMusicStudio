# Nintendo Music Studio 1.5 — complete corresponding source

Windows x64, C++17, Visual Studio2022 Desktop development with C++, CMake3.24+ and Python3. Dependencies are bundled as pinned source archives/trees with notices; no proprietary music is required. Composition/editor sources are absent. Python/Pillow are used only for build/test/package workflows, not runtime.

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build --config Release --parallel 4
python -m pip install Pillow
ctest --test-dir build -C Release --output-on-failure
python tools/audit_licenses.py build
python tools/package_player.py --build build --output dist
```

The legacy build target NintendoGameMusicViewer outputs **build/bin/Release/NintendoMusicStudio.exe**; gme.dll must be beside it. Project/solution name is NintendoMusicStudio. The packaging CLI uses caller-provided paths and requires no private workspace. Test fixtures are generated by bundled own test scripts; no user songs/ROMs/banks are needed. Private-path ExtendedVgmTests/N64ReplacementTests options are optional and music is never packaged. Windows UI tests isolate settings/registration and operate only their own processes.
